D1

The impersonation token

NEXT.md N1

Three defects compound, and all three limbs were verified present:

  • Replayable inside its 2-minute window — session.ts:30
  • Travels in a query string (logs, Referer, browser history) — impersonate/route.ts:22
  • Mints a 7-day session outliving the operator's own — impersonate/route.ts:46

Plus what the architecture map found: no impersonation marker on the minted session (no aud, no operator id, no shortened expiry), so every action taken during it is attributed to the merchant; no revocation (no jti, no token version); and a password reset does not kill it. The only kill switch is deleting the owner's store_users row — which the merchant cannot do to themselves.

The full flow, mapped end to end, with the sequence diagram →

Your options

  • ▸ single-use token
  • ▸ POST body instead of query string
  • ▸ bind the minted session's expiry to platform_session
  • ▸ all three

D3

Login pages publishing seeded credentials

E2

apps/super-admin/app/login/page.tsx:30 prints admin@tokophi.id / tokophi123; the admin login has its equivalent. The seed genuinely creates those rows on deploy.

So on rich.tokophi.com the control plane advertises a working credential on its own login screen.

Your options

  • ▸ delete the hint
  • ▸ or rotate the seeded password

Either way it touches the seed and both apps — which is why it was not taken here.

D4

tokophi_app DML on platform tables

E6

A design decision before the PostgREST cutover, not a patch. Five platform tables carry the COD cap and province allow-list, codAllowed per service, the minimum payout, the enabled payment channels, and plan pricing — with no RLS and no grant restriction — plus a stores policy that is FOR ALL.

It is latent only because the SQL running under tokophi_app today is SQL we wrote. The stated production architecture puts a merchant's own JWT behind that role.

D5

Desktop PageSpeed as a KPI

N3

The measurement says the number tracks the tester's connection, not the build: 15 runs, median 99, range 55–100, TBT = 0 in all fifteen, bytes and request count identical every run. Pearson r against network RTT = −0.866.

Your options

  • ▸ drop desktop as a KPI
  • ▸ or pin it to a fixed measurement host
D6

Speed Index / carousel autoplay

N4

The recommendation is to record it and stop tracking it. Autoplay ON: SI median 7.96 s. Autoplay OFF: 1.87 s, perf 98 / 97 / 97. The page is genuinely complete at 1.8 s — Speed Index scores every frame against the last frame, and an autoplaying carousel guarantees the last frame differs.

The alternative buys score with a carousel that feels dead on arrival.

D8

Abandoned-cart demo data

E4

Un-anchoring checkout.ts is correct, and it drops the Keranjang Ditinggal screen from 796 → 6 on dev because seed:recent inserts no checkout_sessions.

The fix is seeding, not code. Do not re-anchor the app to make the demo look busy.

Stated here so you decide it rather than discover it after the merge. It does not need to block the merge.

D9

tempPassword() entropy

24 bits (randomBytes(3)), and no login rate-limit was found.

Unchanged by this session — resetOwnerPassword already used it — but widening it plus throttling is a real follow-up.

Adjacent detail from the code-health scan: the super-admin copy is randomBytes(3) = 24 bits while the admin copy is randomBytes(4) = 32 bits. Two definitions of the same helper, the weaker one on the control plane.
