build:super explained

apps/super-admin/ has no .env.local (admin has one, gitignored), so Next never receives DATABASE_URL and page-data collection fails. Exporting the root .env makes it build clean, all 13 routes emitted. Any report of “build:super is broken” is this, not a regression.

check-pixel-defer.mjs explained

It asserts all three vendor pixels load, but the seeded store has only the meta channel enabled, so gtag/ttq are undefined. Fails identically on clean origin/main and on all six change sets. The deferral itself is correct — 0 vendor <script src> in the served HTML, 0 vendor requests without interaction, the fbq queue buffers, vendors load on click.

The validation chain has three tools and only one is habitually run

Demonstrated three separate times this session.

  • next build does not run ESLint — ESLint was the only gate that caught a backtick inside a JS template literal that had silently terminated a SQL string.
  • ESLint and next build do not typecheck test files — tsc --noEmit was the only gate that caught a non-overlapping type assertion in a newly added test.
  • tsc, ESLint, astro check and the build are all green on live outages — this is the repo's own documented history (a ReferenceError inside a client <script>; select sum(…) for update inside a SQL string, which Postgres rejects outright).

Recommendation: run all three plus the browser checks before any PR. Currently nothing runs ESLint automatically, which is how it rotted to 19 errors.

Method — and why ten worktrees

Ten agents ran in parallel, each in its own git worktree branched from origin/main, because AGENTS.md records that concurrent agents sharing one checkout have already caused an outage (queueSave is not defined, which blocked the entire shipping-rate load — no rates → no COD → no order — while typecheck, lint and build all stayed green).

Corrections made during the session are kept visible on purpose — several agents disproved claims from the task list, from the repo's own docs, and from each other. Those disproofs are findings, not noise.

Nothing has been committed. All work sits uncommitted in worktrees under .claude/worktrees/ for you to review and commit via lazygit.

Constraints imposed on every agent

  • ✗ no commit, no push, no PR, no merge
