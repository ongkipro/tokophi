## Scope

Ship the two deferred findings recorded in `2026-08-12-postship-audit.md` — exactly those, smallest
diffs, no shared-config touches:

- **D1 — `packages/db/src/seed-platform-theme.ts`.** The copy-source lookup is
  `inArray(slug, SOURCE_SLUGS).limit(1)` with no ORDER BY, so the "preference order" the comment
  promises is plan-dependent. In the one both-slugs state (rename blocked: a foreign store holds
  `batiknusantara`, demo still on `batik-nusantara`) the wrong pick copies a MERCHANT's templates as
  the platform default. Fix = the audit's recorded shape: one `eq(slug)` per `SOURCE_SLUGS` entry,
  in declared order (`batik-nusantara` first — that IS the demo store in the anomaly, per the audit;
  in every other state only one slug exists and order is moot), stop at the first hit. Comment
  updated to tell the truth. Unreachable on prod today (holder has all 3 types) — still wrong.
- **D4 — `apps/storefront/src/middleware.ts`.** The slug-rename 301 builds `newHost` from the
  NORMALIZED host, which has the port stripped — so
  `batik-nusantara.127.0.0.1.sslip.io:4327` redirects to a portless host nothing serves. Fix =
  take the port off the RAW Host header and append it to the redirect Location. Prod hosts carry no
  port → empty string → Location byte-identical.
- **D2 — deliberately NOT done here.** A behavioral pinning test for the 301 still needs an
  `astro:middleware` (virtual module) alias stub in the shared vitest config / `test/stubs/` —
  verified absent on this base — and that config is shared infrastructure other streams own. Any D4
  source-claim test pins the port shape only; it is not the D2 behavioral pin.
