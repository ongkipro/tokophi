# Task 5.5 — Remove the Shared 320 px Seller Topbar Overflow (F-F11, NF-7)

**Date:** 2026-08-24 · **Executor:** Lane B (Claude subagent) · **Branch:** `fix/task-5.5-topbar-320` (off `origin/main` `64458fe`)
**Status:** DONE — audit 24/264 broken → 0/264, full suite green, browser-verified at 320/360/768/1280 px.

## What was wrong

`apps/admin/scripts/audit-responsive.mjs` against a production build reported **24/264 route×width
checks broken — every seller route, only at 320 px, overflowing by 38 px**. The culprit it printed on
every route was the same element: `div.ml-auto` — the topbar's right cluster (232 px wide), dominated
by the balance chip rendering a real balance ("Rp214 jt"). The topbar is one shared component
(`components/admin/topbar.tsx`), which is why all 24 routes failed identically and why the fix is one
file, not 24.

## ⚠️ The trap: a Rp0 store makes this audit pass vacuously

The first baseline run used a probe user on `tas-rajut-handmade` (ledger sums to **Rp0**) and reported
a clean `OK — 264`. The chip renders "Rp0" — narrow — and nothing overflows. **The overflow only
reproduces against a store whose balance is wide** (`batiknusantara`, Rp214.283.232 → "Rp214 jt").
Anyone re-running this audit to check the topbar must log in as a wide-balance store, or the audit is
measuring a layout the seeded demo never shows.

## The fix (component boundary — nothing hidden, nothing per-route)

All in `topbar.tsx`, plus the topbar's own search trigger in `command-palette.tsx`:

1. **Below 360 px the balance chip drops its amount TEXT only** (`max-[359px]:hidden` on the span).
   The wallet icon keeps its place in the bar, the chip still links to `/saldo`, and the `aria-label`
   always carries the full amount — so the money stays one tap away and fully announced to a screen
   reader. Deliberately *not* truncation: a clipped "Rp214…" reads as a different balance.
2. **Below 360 px the store switcher drops its decorative chevron.** The 2-letter store badge — the
   identity — stays at every width; the button is still an obviously-tappable dropdown trigger.
3. **Touch targets ≥ 40 px without spending width:** `HIT = "relative after:absolute after:-inset-1"`
   overlays a 40×40 hit zone on each 32 px control (menu, switcher, search, saldo, theme, bell,
   avatar). Verified in the browser: the `::after` pseudo-element computes `position:absolute;
   inset:-4px`. Widening the *boxes* instead would have re-created the 320 px overflow (4 icon
   buttons × 8 px = the 38 px again).

At ≥360 px nothing changes; at ≥640 px (`sm`) and up the bar is pixel-identical to before.
