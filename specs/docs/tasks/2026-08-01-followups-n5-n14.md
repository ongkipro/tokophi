## ✅ ① N14 — every store's homepage shipped THREE `<h1>`s · **S** · **DONE 2026-08-01**

`Hero.astro` rendered the heading **inside the slide loop**, so a 3-slide carousel emitted three
`<h1>`s. Confirmed on production (`curl -s https://toko.tokophi.com/ | grep -c '<h1'` -> **3**) and
re-confirmed locally against a real build (`h1 3`).

**Shape chosen: `<h1>` on ONE slide, `<p>` in the identical class list on the rest.** Rejected the
hoisted single `<h1>`: the heading then cannot change per slide, which is half of what a hero
carousel is for. Rejected `<h2>` on the rest: they are not sub-sections of slide 1, they are the same
banner in another state — a `<p>` is the honest tag, and the class list is shared as one constant so
the two can never look different. The cross-fade survives untouched: nothing is unmounted, nothing in
the script selects `h1` (it drives `[data-hero-copy]`), and `inert` is applied per slide either way.

⚠️ **It was slide `HEADING_INDEX`, not slide 0** — a third live defect turned up while fixing this:
`heroSlides()` deliberately keeps a slide with an `imageUrl` and NO heading, so
  - a hero whose slides have no heading rendered `<h1></h1>` (an element with no heading in it), and
  - N11's floor stood down over it, because it keys on `s.type === "hero"`.
Measured against that template on `origin/main`: **`h1 2`, both empty**. Both halves now ask the SAME
question — "is there a slide whose heading is non-blank" — so they cannot disagree.

- [x] Decide the shape (recorded above and in the commit body).
- [x] Implement in `apps/storefront/src/components/sections/Hero.astro`.
- [x] Extend `sections/h1-floor.test.ts` — it now pins that BOTH halves key on the heading text, which
      is the premise a count alone cannot see. The count itself is pinned over HTTP (below), because a
      unit test cannot see a template that lives in the database.
- [x] **AC:** exactly one `<h1>` in the SSR response for the seeded 3-slide hero — over HTTP, against a
      real build. `apps/storefront/scripts/check-h1-floor.mjs`.
- [x] Re-check the floor: hero-less template ⇒ still exactly one `<h1>`. Plus the new third case,
      heading-less hero ⇒ exactly one, and it is the floor.

⚠️ **PART OF THIS LANDED 2026-08-01 (audit wave 2) — read
[`2026-08-01-audit-wave-2.md`](./2026-08-01-audit-wave-2.md) ① before starting.** `Stars.astro` was
**312 elements, 30 % of the page**, and the rewrite took the homepage **1023 → 915** (−10,6 %) with
`dist/client` unchanged. **Both candidates below were measured and KILLED** — do not spend an afternoon
re-deriving them:

- *defer the carousel slides* — buys ~30 elements of a 106-element hero, and costs the crawler and the
  no-JS reader the copy;
- *cut what the default template seeds* — **zero delta by construction**. The seed is not a migration, so
  it reaches new stores only.

915 is under Lighthouse's 1400 median and still over its 800 p10 — the audit improves without passing.
**The next largest repeats are the header and footer lucide icons.** Measure them before assuming.

🔴 **`SectionRenderer` must keep switching on every type.** Narrowing the palette stops merchants
adding more; deleting a branch **silently deletes published work** from templates saved earlier
(AGENTS.md, Store Builder). Narrow the palette, never the renderer.

⚠️ **The seed is not a migration.** Changing how many sections the default template seeds with reaches
**new stores only** — production keeps what it was given the first time. If existing stores need it
too, that is a data fix, and it must be stated in the commit body because nothing else will apply it.

  --throttling.rttMs=40 --throttling.throughputKbps=10240 --throttling.cpuSlowdownMultiplier=1 \
  --quiet --chrome-flags="--headless=new --no-sandbox" --output=json --output-path=./d1.json

  --chrome-flags="--headless=new --no-sandbox" --output=json --output-path=./m1.json

a script — that is the single check that overturned N7.
